# CLAUDE.md — how to work in this repo

Guidelines for any AI coding agent (and humans) changing the Hidden Gold Clusters bots.
Adapted from [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills)
(MIT), made concrete for this project, with three rules added from mistakes we actually made.

**Tradeoff:** these rules favour caution over speed. For a one-line config tweak, use judgment.

## The project in one paragraph

We write bots for Cambridge Battlecode 2026 Autumn (`cambc2026a`). The submitted bot is
`bots/goldrush-cpp` (C++). `bots/goldrush` is the Python original: it is the behavioural
reference and the fallback submission. `bots/goldrush-vN` and `bots/goldrush-cpp-vN` are frozen snapshots used as
regression opponents. Rules of the game live in the official handbook on
<https://2026a.battlecode.co.uk>; check them there rather than answering rules questions from memory.

## 1. Think before coding

- State your assumptions: which bot, which maps, which side, which version is live on the ladder.
- If a request has more than one reading, say which you picked and why. If the user is around
  and the choice is expensive to undo, ask first; if they are away, pick the cheapest-to-undo
  reading and say so at the top of your reply.
- Push back when a request will not achieve its goal (example: "rewrite in C++ to win more" —
  the losses were strategy bugs, not language).

## 2. Simplicity first

- One change per experiment. Prefer changing a number in `config.h` / `config.py` over new logic.
- No speculative features, abstractions or options. If 200 lines could be 50, rewrite it.
- Catch engine errors where a call can fail mid-turn (units leave vision, channels block
  actions); do not add handling for things that cannot happen.

## 3. Surgical changes

- Every changed line must trace to the request. Do not reformat or "tidy" unrelated code.
- Never edit: `sdk/`, `maps/`, `cmake/`, `bots/starter-*` (all regenerated by `cambc init`)
  or a frozen `-vN` snapshot (that would silently move the goalposts).
- A behaviour change goes into **both** `goldrush-cpp` and `goldrush`, or the CHANGELOG says
  which one diverged and why.
- Remove only the dead code your own change created.

## 4. Goal-driven execution

Turn every task into a check you can run, then loop until it passes:

| Task | Done when |
| --- | --- |
| Strategy change | `make eval OPPONENT=<latest snapshot>` wins **≥ 10 / 18**, and `make eval` vs `starter-python` does not drop below the current score |
| Bug from ladder logs | the error no longer appears: `make eval` prints `errors=0` |
| C++ port / refactor | same results as before on all 18 games, and `make eval` prints `fuel_warnings=0` |
| Shipping | `make bundle` produces the ZIP, and its contents are listed in the reply |

For multi-step work, write the plan as `step → verify: check` before starting.

## 5. Measure, don't assume (added)

- **Compute budget:** C++ gets 100k fuel per turn, Python 2.5M. The first C++ port used 91% of
  its budget on `lanes` (Python used ~50%) because of per-turn full-map bitboard allocations.
  The bot prints `goldrush warning: turn ran out of fuel` whenever a turn is cut short, and
  `make eval` counts those lines; check ladder logs for it too.
- **Ladder ≠ local:** the ladder uses maps we do not have locally. The 0-gem "oscillating
  champions" bug never happened on our 9 maps. Always analyse downloaded ladder replays
  (`docs/MATCH_LOG.md`) before trusting local win rates.

## 6. Evidence over claims (added)

- Paste the real numbers from `make eval`, never a summary of what "should" happen.
- Never claim a check you did not run. A change that builds but has no match result is unfinished.
- Log every experiment in `CHANGELOG.md`, including the rejected ones and their score.
- After each ladder match group, add a dated section to the top of `docs/MATCH_LOG.md`.

## 7. Keep a known-good submission (added)

- Before a deadline, upload a safe bundle first, then experiment.
- Snapshot before changing behaviour: `make snapshot V=<n>` (freezes the current bot as
  `bots/goldrush-cpp-v<n>`).
- Only replace the live submission with a version that passed rule 4.

## Commands

```bash
make setup                          # cambc, SDK, starter bots, map pool
make build                          # compile goldrush-cpp
make match MAP=lanes                # one game vs starter-python
make eval                           # 9 maps x both sides vs starter-python
make eval OPPONENT=goldrush         # C++ vs the Python reference
make snapshot V=6                   # freeze bots/goldrush-cpp as bots/goldrush-cpp-v6
make bundle                         # dist/goldrush-cpp.zip, ready to upload
make test && make lint              # Python unit tests and style checks
```
